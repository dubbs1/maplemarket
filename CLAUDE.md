# Notes for developers (and Claude Code)

How the project works and the decisions behind it, so new work picks up where the last left off. The user-facing guides are `README.md` and `MapleReader/GUIDE.md`.

## Who it's for

- The owner is a beginner on Windows. Give **step-by-step instructions**, one action per step, each with "You should see …" and "If … then …". Plain words; avoid jargon or explain it once.
- Their PC: Windows, Python 3.13 as `py -3.13`, Tesseract 5.5.3 in `C:\Program Files\Tesseract-OCR`; the app installs per user from the Releases page.
- **Updates** reach them through the installer on the Releases page (the app offers them itself once releases are public); a zip over the folder also works, and then the **full** folder must be sent whenever files were added.
- They also run **Rev Market** (vendormarket.app), a separate Ragnarok Online market site on its own server. It must never be touched by Maple work: Maple stands alone (the group market that once ran on Vercel + Supabase under `maple.vendormarket.app` was removed on 2026-10-24: everything stays on the owner's PC). Rev Market's design language (clean, everything visible, no hover-only controls, cards never touching, item pictures on rows, "just listed" in green) is the standard for this UI too.

## Hard rules

- **Passive only.** No packet sniffing, no auto-clicking, scrolling or typing, no game-memory reading. Screenshots + OCR only. Nexon has not said screen readers are allowed; the guide says so honestly.
- **Don't copy other sites' data** (MeowDB, MesoWatch, planet-helper and others). Link only.
- **No "MapleStory" in product or domain names** (Nexon's trademark). "Maple" and "meso" are fine.
- **Never edit Rev Market's files, service or server.** Nothing of Maple lives on that server.

## How it fits together

```
Game window --screenshots--> MapleReader (scanner thread)
   reads rows (Tesseract), sold/faded rows, scroll position, room (minimap), channel (Change Channel window)
   -> scans/scan_<date>.txt + scans/all_scans.txt   (one line per listing)
   -> scans/icons/<slug>.png                         (item picture cut from the shop row)
   -> app server http://127.0.0.1:8765 -> app window (Edge --app mode) showing market.html
```

### Scan line format (all_scans.txt)
`item | price each | shop | room | channel [| sold] [| gone] [| c<copy>] [| @YYYY-MM-DDTHH:MM:SS±HH:MM]`

- `gone` = the reader saw that shop's **whole** list again and this listing wasn't in it (bought, taken back, re-priced); the page sets it from for sale to gone (never makes a listing of it). Sold ones aren't gone: they show faded. For timed rows the page marks listings gone **only** from these lines (a later look that saw part of a shop must not hide the rest); old untimed snapshots still infer it. A sold `c1` seen at the same moment as a for-sale `c1` is a second copy (`K + "|s"`). Rows without `c` are numbered within one second (one look), not a whole session.
- `c2` = the 2nd identical listing in that shop. The reader numbers copies, so a shop seen twice merges the same way.
- The time carries the PC's UTC offset (reader version 2026-10-20c and later), so ages are right whatever the PC's time zone. Older lines may lack the offset (read as the viewer's local time), `c` or `@time`; the page still imports them.
- Rooms: the wiki lists 11, but the page and the black window accept 0 to 40 (0 = not read), in case more open at launch.

### Market page modes (`MODE` in the page script)

| Mode | When | What it does |
|---|---|---|
| `local` | served by the app (127.0.0.1) | Scan tab, live feed from all_scans.txt |
| `static` | the page opened as a plain file (no server) | sample data, manual import |

In live modes the page keeps 30 days in the browser's localStorage (about 40,000 listings fit): `importScan` doesn't store rows older than that, `pruneOld` runs at load and once an hour (the window stays open for days), and when the browser says storage is full, `saveRoom` drops the oldest scans until it fits (a single long session loses its oldest tenth of rows). `item()` uses an id→item Map and `itemByName` a lowercase-name Map (ITEMS grows with every OCR'd name; 40,000 lines once took 2.6 s of `ITEMS.find`). Live pulls (`importScan(text, true)`) save 5 s later, all at once (`saveSoon`, flushed on `pagehide`), and only the sessions that got rows are re-numbered; `HAVE` (the set of stored row keys) is kept between pulls and set to null wherever rows are dropped or change item. `scanAll` walks a session's rows in time order, not arrival order (t14 G6: an older "for sale" row arriving after this PC's gone line). The page asks its own app every 2 s (`EVERY` in `puller`). Items someone typed (`typed: 1`) are never renamed by `tidyNames`.

**Simple layout (`SIMPLE`, = the app's live mode: a much easier user experience).** The look (2026-10-24c, "Maple": Nunito + JetBrains Mono for numbers; a warm maple palette as tokens on `:root`, day (cream `--bg`, orange `--ac` for actions, deep maple `--sky` for links and selected states, `--gold` for big numbers, `--leaf` green) and night (`data-theme=dark` and `prefers-color-scheme`); rounded cards with a soft shadow (`--shadow`) that never touch; glossy orange action buttons; an original maple-leaf mark, no Nexon artwork): one header on every tab with the name, a **search box (`#gs`, `#gsf`)** that searches the Prices tab from wherever you are (`searchBox()` = `#gs` in live modes, the page's own box in static; `showPrices()` is the one way to the Prices tab) and the status pill `#chip` ("Watching · CH 10 · Room 2"); **pill tabs** (`html.app nav`, the current one filled orange, Options set apart on the right); **the app window is one size** (`html.desk` when `MODE === "local"`: `main` is the window's height, header and tabs stay put, `#app` scrolls inside; `desktop._lock_window` takes the resize border and Maximise button off the Edge window: the one owned by the browser process it started, or, if that handed over to a running copy, the one titled `WINDOW_TITLE` = the page's `<title>`; `WINDOW_SIZE` is the one place the 1240×860 lives; the exe self-check looks for the title in the page). ## Building and releasing

- **Dependencies are pinned:** `MapleReader/requirements.txt` (mss, pillow, pytesseract; used by `setup.bat` and CI) and `requirements-build.txt` (+ PyInstaller; `build_exe.bat` and the Windows job). Bump them on purpose, run the checks, and audit them: `pip install pip-audit && python -m pip_audit -r MapleReader/requirements-build.txt` and `npm audit` (2026-10-24: Pillow 12.3.0 had 37 published CVEs, all fixed in 13.0.0; the fix was to move to 13.0.0, which passed every check unchanged). The release action is pinned to a commit SHA (it can write releases); the other actions ride their major tags (v7/v8 run on Node 24, which GitHub's runners have). `choco install tesseract` is not pinned (the picture checks tolerate 5.3 vs 5.5).
- `MapleReader/build_app.py` builds the exe (PyInstaller); `build_exe.bat` calls it. `MapleReader.exe --self-check out.txt` starts the app's parts in a scratch folder and writes PASSED/FAILED (the exe has no console); exit code 0 = good.
- `MapleReader/installer/MapleReader.iss` (Inno Setup 6): per-user install to `%LOCALAPPDATA%\Programs\MapleReader`, no admin, Start-menu + desktop icon, `_internal` replaced whole on update, data next to the app kept.
- `.github/workflows/checks.yml`: **linux** on every push (pyflakes, `run_all.sh`); **windows** on main, PRs, `v*` tags, manual runs, or a commit message containing `[windows]` (Windows minutes cost 2× on a private repo): reader checks with real Windows Tesseract, build exe, self-check it, build installer + `.sha256`, silent install, self-check the installed copy, uninstall; uploads the installer as an artifact. **release** on main (or a `v*` tag; the Windows job refuses a tag that doesn't match `__version__`) publishes the installer + `.sha256` as `v<__version__>` unless that release exists.
- To release: bump `__version__` in `shopreader/__init__.py` and merge to main: the **release** job publishes `v<version>` by itself when that release doesn't exist yet (a Claude Code session can't push tags or write through the GitHub API, so releases must not depend on a pushed tag). A pushed `v*` tag still works too.
- First green run: 39400495762 (both jobs). Lessons: in the Windows steps never use `Start-Process -Wait` (it also waits for the MapleReader the setup starts: the first run hung for an hour); wait with `$p.WaitForExit(ms)`. Pushes don't cancel each other's runs (concurrency is per commit; only pull requests replace older runs). A Claude Code session's network can't download run artifacts (blob storage is blocked); the owner downloads the installer from the run page.
- **Build minutes:** the merge of PR #16 (v2026-10-21g) had both jobs stop 2-4 s after starting, no steps run, no log, twice (a re-run too); every earlier run was fine, and PR #17's run died the same way. That is what GitHub does when a private repo's Actions minutes or spending limit is used up (Windows minutes count 2×). The ways out: check github.com/settings/billing; make the repo public (unlimited minutes, and the app could update itself), wait for the month to reset, or set a small Actions budget. Until a build runs, no release after 2026-10-21f exists.
- **The repository is private:** release downloads need a GitHub login, so installed apps report "Updates: none published yet". Updates reach users only once releases are public (make the repo public, or publish releases from a public repo and point `UPDATE_REPO` at it). Ask the owner.

## Known open items

- **Name misreads:** `names.fix_w` also fixes a W read as up to three marks after a hyphen ("Ink-and-vVYash", "-¥Wash", "-WYash", "-v¥Vash"; a real "Wy…" is kept), and W's are fixed before stray leading symbols are stripped. The page has the same rules (`fixW`, `fixName`: used on every scan line it reads, and `tidyNames` folds items an older page saved under misread names into the right one at start-up; `tests/test_names.py` compares the two, t17 tests the page). Tesseract 5.5 sometimes reads "Mystery" as "Iystery" on quick re-reads, and single-letter shop names ("S" → "3"). `names.fix_w` turns a capital W read as two marks at a word's start (Vv, Yw, yy, Y¥, ¥¥…) into W, for items and shop titles; "Biue"/"Hiue"/"bIUe" → "Blue". At other interface sizes about 90-95% of listings read right (was 68-80%); blurry "Filter Applied" text is the hardest. An `items.txt` list fixes names.
- **EXP digit shapes:** `tools/make_exp_font.py` cuts them from test pictures at the usual interface size (live_shop, desk_live, s711, and `status38.png`, the owner's bar at level 38 with EXP 36,420 / 240,500 from the game's tooltip; the other-size pictures test the reading). Every digit of the small font is real now (the hand-drawn 5 in `MADE_UP` is only used if no picture has one). The level tiles' font has **3, 7, 8, 9** only (9 from `kerning_inv.png`, level part only): other level digits are never guessed (`TILE_MATCH`, no Tesseract): the level shows "—" until known, and once known the tracker counts level-ups itself instead of re-reading it. To add digits: put a screenshot with a known status bar in `tests/fixtures`, add it to `SOURCES`, run the tool, run `tests/test_exp.py`. At 0.6× interface size the digits are too small: readings are skipped, never wrong.
- **Stack counts:** the numbers on item icons (e.g. 100) aren't read yet; every listing counts as quantity 1.
- **Fast scrolling:** flicking or dragging straight to the bottom of a long identical list undercounts (by design it never overcounts).
- **Untested for real:** the Edge app window on the owner's PC. Ask for screenshots or output on the first run.
- **Possible next steps**: recognise items by their icon to fix misread names; the MapleClassic Wiki item list (CC BY-SA, credit) for names and categories; Windows notifications for alerts; stack counts; a "report a problem" button; CSV export.
